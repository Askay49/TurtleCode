# Работа с большими текстами

В **Настройки → Редактор… → Шрифты** можно отдельно выбрать установленный шрифт и его размер (6–96 пунктов) для дерева проекта, текста редактора и будущего терминала. Сохранение сразу обновляет открытые редакторы и деревья проекта во всех окнах; новые окна используют сохранённые значения. Отмена диалога ничего не меняет. Пока терминал отсутствует, его настройки только сохраняются. По умолчанию дерево использует системный интерфейсный шрифт, а редактор и терминал — системный моноширинный.

Настройки истории: **Настройки → Редактор…**. По умолчанию каждому документу выделено 64 МиБ для текста Undo/Redo в оперативной памяти. Превышение переносится во временные файлы. Дисковый лимит по умолчанию — 0, то есть без ограничения. Это история текущего сеанса, она не восстанавливается после перезапуска.

Если отключить дисковое хранение, история ограничивается заданным объёмом RAM. Если задать дисковый лимит, при его превышении удаляются самые старые действия. Об этом редактор сообщает в строке состояния. Сам текст документа и отметка сохранения от удаления истории не меняются. Настройки применяются к открытым документам; для занятого документа — после окончания операции.

При открытии файла от 4 МиБ первая порция текста показывается до завершения индексации. Полный файл читается и индексируется в фоне, с индикатором и отменой. До окончания индексации доступен просмотр начальной порции, редактирование заблокировано. После индексации становится доступен весь документ. Чтение идёт через собственную временную копию, поэтому внешняя замена исходного файла не повреждает открытый текст.

Длинные строки от 64 КиБ рисуются только в видимой области. Для них используется облегчённый режим: одинаковые ячейки, без синтаксических цветов и сложного формирования глифов. Переходы к строке/столбцу используют индекс Unicode; навигация по словам и составным символам ограничивает окружающий контекст восемью КиБ с каждой стороны. Это компромисс для патологически длинных строк; обычные строки сохраняют полное поведение Unicode.

Большие вставки, вырезание/копирование, массовая замена и дисковые Undo/Redo готовятся в фоне. В процессе документ доступен для просмотра. Отмена оставляет его текст и историю прежними. Изменения применяются целиком после успешной подготовки. При сохранении данные пишутся порциями в новый файл, затем атомарно заменяют исходный.

Обычный поиск читает порции с перекрытием и работает в том числе внутри огромной строки. Поиск по регулярным выражениям пропускает строки длиннее 256 КиБ; это указано в подсказке счётчика. Выдача ограничена 10 000 совпадений. При достижении этого числа «Заменить всё» блокируется до уточнения запроса.

Вставки от 1 МиБ сразу сохраняются на диске; накопленные небольшие вставки переносятся туда при достижении 4 МиБ. Внутреннее копирование больших выделений также использует временный файл. Системный буфер обмена при чтении из другого приложения всё ещё может потребовать целую строку в RAM.

Лимит истории ограничивает её текстовые данные, а не всю память приложения. Индекс фрагментов, кэши, разбор синтаксиса, данные LSP и системный файловый кэш учитываются отдельно. При ошибке записи истории редактор сохраняет доступную историю и сообщает об ошибке: в таком случае лимит RAM может временно превышаться.

Временное хранилище использует TMPDIR или /tmp. Ему нужно место для копии исходного файла, вставок и истории. Файлы освобождаются после исчезновения последних владельцев; фоновая операция или внутренний буфер обмена могут удерживать их после закрытия вкладки. В дисковом хранилище вставок освобождение отдельных удалённых участков пока не реализовано: место возвращается при освобождении всего хранилища. Ограничение диска в настройках относится к истории, а не к копии открытого файла или вставкам.

Проверки покрывают Unicode, дисковую историю и её лимиты, отмену вставки, массовую замену с Undo/Redo, начальный просмотр, ограниченный обход длинных строк и атомарное сохранение. Предыдущий замер на миллионах строк повторно не запускался.
