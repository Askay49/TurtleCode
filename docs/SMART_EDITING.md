# Удобства редактирования кода

## Ввод и выделение

- Ввод `(`, `[`, `{`, `"`, `'` создаёт закрывающую пару и оставляет курсор внутри.
  Перед словом лишняя закрывающая пара не вставляется. `<` не образует автопару.
- Ввод уже стоящей перед курсором закрывающей скобки или кавычки переводит курсор
  через неё. Для кавычек учитываются контекст строки и экранирование.
- Backspace между пустыми парными символами удаляет оба одним действием.
- При выделении открывающая скобка или кавычка оборачивает текст и оставляет
  внутренний текст выделенным, включая обратные выделения и несколько курсоров.
- Пары не добавляются внутри распознанных строк и комментариев. Вставка из
  clipboard и IME commit остаются буквальной вставкой текста.
- Enter копирует отступ текущей строки. После `{` добавляется один уровень
  (4 пробела; при табуляции в конце исходного отступа — табуляция). Между `{}`
  Enter создаёт внутреннюю строку с отступом и отдельную строку закрывающей скобки.
  Сохраняется LF/CRLF по первому переводу строки документа, BOM не добавляется
  к отступу. Дополнительные отступы внутри строк/комментариев не создаются.
- Tab с выделением сдвигает затронутые строки на 4 пробела; Shift+Tab снимает
  до 4 пробелов или одну ведущую табуляцию. Выделение и его направление остаются
  активными. Конец выделения в начале следующей строки не включает эту строку.
  Без выделения Tab вставляет 4 пробела, Shift+Tab уменьшает отступ строки.

Настройки → Редактор → **Автоматически закрывать скобки и кавычки** управляет
автопарами, пропуском закрывающего символа, парным Backspace и оборачиванием
(`editor/autoPairs`, по умолчанию true). Отмена диалога ничего не меняет.
Ввод и команды проверяются на занятость документа. Содержимое диалога настроек
прокручивается, а кнопки Save/Cancel остаются снаружи области прокрутки.

## Комментарии

- **Ctrl+/** — закомментировать / раскомментировать строки.
- **Ctrl+Shift+A** — закомментировать / раскомментировать блок.

Обе команды находятся в меню **Код** и переназначаются в настройках сочетаний:
`editor.toggleLineComment`, `editor.toggleBlockComment`.

Для C/C++ применяются `//` и `/*…*/`. Отступ каждой строки сохраняется; пустые
строки многострочного выделения пропускаются. Если все непустые строки уже
закомментированы, команда снимает комментарии; иначе добавляет их.

Для Python, shell, Ruby, Perl, CMake, Make, Meson, Nix, Dockerfile, Nginx, YAML
и TOML используются `#`; для Lua и SQL — `--`, для INI/assembly — `;`,
для HTML/XML/Markdown — `<!--…-->`. В CSS используются блочные комментарии. JSON не комментируется: команда показывает
сообщение, не изменяя документ.
В языках без настоящих блочных комментариев команда блока переключает строковые
комментарии. Для неизвестного расширения действует C-подобный fallback.
Вложенные границы блочных комментариев при оборачивании отвергаются до правок;
в таком случае следует использовать строковые комментарии. Это не команда LSP.

## Подсветка парной скобки

Рядом с основным курсором подсвечиваются соответствующие `()`, `[]`, `{}`.
Парные скобки имеют рамку акцентного цвета темы, подтверждённая непарная скобка —
рамку цвета ошибки. Символы в распознанных строках/комментариях пропускаются.

`CodeContext.hpp` предоставляет независимый от установленных грамматик лексический
fallback: C-подобные строки/комментарии, C++ raw strings и числовые разделители,
а также базовые правила перечисленных выше языков, включая Python triple strings.
Это не полноценный синтаксический анализатор каждого языка реестра: в частности,
JS regex literals, интерполяции и все специфические формы строк других языков
не моделируются. Tree-sitter и LSP не заменены и не отключаются.

Контекст кэшируется в разреженных checkpoints (до 4096), инвалидируется от правки
с запасом для многосимвольных разделителей и дочитывается срезами до 128 КиБ.
Поиск пары ограничен 128 КиБ в сторону поиска, debounce — 25 мс. Если контекст
ещё не готов, он постепенно дочитывается таймером; автопара консервативно не
добавляется. Недостижимая в ограниченном поиске скобка не объявляется ошибкой,
если конец документа/начало не были проверены. Поиск не копирует весь документ.

## История, большие выделения и проверка

Каждая команда изменения образует отдельный Undo step. Существующие границы
истории сохраняются; Undo/Redo восстанавливает текст и курсоры, но якоря выделений
в истории проекта по-прежнему не хранятся.

Строковые команды для области от 1 МиБ или более 4096 строк готовятся через
существующий фоновый staged-buffer механизм с отменой. Отмена не меняет документ;
выделение восстанавливается после успешного применения. Изменения передаются
существующим механизмам Tree-sitter/LSP/recovery.

Отдельный тест:

```sh
cmake --build build --target turtle-code-editor-tests -j4
ctest --test-dir build -R '^smart-editing$' --output-on-failure
```

Проверяются пары/пропуск/Backspace, буквальная вставка, строки и комментарии,
raw strings, экранирование, Unicode, направления выделения, мультикурсор,
Enter, BOM/CRLF, Tab/Shift+Tab, переключение комментариев, Undo/Redo,
бюджетный контекст, большое выделение/отмена и offscreen-отрисовка рамок.
`window-shutdown` дополнительно проверяет меню, применение и отмену настройки.
Реальная desktop-сессия и аппаратный IME этой проверкой не заменяются.

## Доставка Tab в интерфейсе

`EditorWidget::event()` принимает Tab и Shift+Tab до стандартного переключения
фокуса QWidget, только когда фокус принадлежит самому редактору. Обработчик
ввода выполняет отступы, включая блокировку во время фоновой операции. Ctrl/Alt/Meta
не перехватываются этим правилом; поля поиска/замены используют обычную навигацию
по элементам. В popup автодополнения Tab подтверждает выбранную подсказку через существующий
обработчик activated с проверками ревизии и позиции; остальные клавиши обрабатывает
QCompleter.

Регрессионный тест направляет клавиши через `QWindow`, размещая рядом с редактором
кнопку, доступную по Tab. Это воспроизводит прежнюю ошибку, которую не обнаруживал
тест отдельного редактора без соседних элементов. Проверяются одиночный Tab,
оба варианта Shift+Tab, выделенный блок, сохранение фокуса, busy, переход из поля
поиска и Tab в completion popup. Дополнительная проверка есть в настоящем MainWindow.
