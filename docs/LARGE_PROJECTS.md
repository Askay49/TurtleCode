# Большие проекты

Файловый индекс, список каталога и результаты поиска используют временные SQLite
хранилища. Кэш SQLite и кэш прочитанных совпадений ограничены; полный текст всех
совпадений не хранится в RAM. Хранилища удаляются после освобождения их владельцев.
Они используют системный временный каталог: для крупных операций нужен свободный
объём. Если `/tmp` расположен на tmpfs, можно задать `TMPDIR` на дисковый каталог
перед запуском приложения.

## Файлы проекта и Ctrl+P

В Git-репозитории правила `.gitignore`, вложенные исключения и настройки Git
проверяются через libgit2. Без репозитория поддерживаются локальные `.gitignore`
с масками, отрицаниями, привязкой к каталогу и `**`. Дополнительно действуют
`.turtleignore` и список масок QSettings `project/excludes`. Служебная `.git`
и симлинки не обходятся. Скрытые файлы управляются отдельно.

Команда **Вид → Включать игнорируемые файлы** позволяет явно включить исключённые
файлы. Это применяется к дереву, индексу Ctrl+P и поиску. `.git` остаётся исключённой.

Индекс живёт в течение окна и повторно используется при открытии Ctrl+P. Предела
150 000 файлов больше нет. Каталоги и их состояния хранятся на диске; повторная
проверка перечитывает содержимое изменившихся каталогов. Изменение локальных
ignore-файлов вызывает перестроение. Изменения внешних Git exclude-настроек
подхватываются при повторном открытии проекта.

Проверка индекса запускается после уведомлений дерева, при открытии Ctrl+P и
периодически раз в 30 секунд. Файлы из ещё не отслеживаемых каталогов могут
появляться с задержкой. Начальное заполнение публикует промежуточные части;
интерфейс показывает, что индексация продолжается.

Поиск Ctrl+P выполняется в отдельном пуле; в интерфейс возвращаются лучшие
100 результатов. Это размер выдачи, а не ограничение доступной части проекта.
Устаревшие запросы отменяются. Без явно выбранного проекта выдача ограничена
открытыми файлами, домашний каталог не индексируется для Ctrl+P.

## Поиск и замена

Совпадения и SHA-256 файлов записываются во временные базы. Прогресс передаётся
через один заменяемый почтовый ящик, без неограниченной очереди сообщений.
Публикуются результаты полностью проверенных файлов; частичные данные бинарного
или некорректного UTF-8 файла не предлагаются для замены.

Длинная строка читается блоками, преобразуется в UTF-16 и при необходимости
выносится во временный файл с отображением в память. Preview ограничен небольшой
областью возле совпадения. Регулярные выражения используют PCRE2 с проверками
отмены и бюджетами времени/памяти/глубины. При превышении бюджета весь файл
исключается из результатов, а панель показывает число пропусков и детали в
подсказке статуса. Это явный неполный результат, а не успешный полный поиск.
Большие захваты regex по-прежнему требуют памяти для самого захваченного текста.

Панель показывает по 500 файлов на странице и загружает совпадения по запросу.
Отметки выбора сохраняются между страницами. По умолчанию выбраны все найденные
совпадения, включая другие страницы. Замена становится доступна после завершения
поиска. Операция читает выбранные совпадения в порядке файлов/смещений из базы,
потоково пишет QSaveFile и проверяет прежний SHA-256 перед commit. Открытые
изменённые/занятые документы защищены. Отмена действует между блоками и файлами;
уже завершённые файлы сохраняют применённые изменения.

## Дерево, наблюдение и Git

Список каталога читается в фоне и сохраняется на диске. Дерево показывает страницы
по 500 записей; добавление строк разделено на короткие порции GUI. Существующие
узлы текущей страницы сохраняются при обновлении. Наблюдение объединяет серии
событий; при неудачной установке watcher работает резервная проверка.
Удаление каталогов выполняется в фоне и допускает отмену. После отмены часть
содержимого уже может быть удалена; это явно сообщается пользователю.
Периодический сбор состояний открытых документов также вынесен в фон.

Git не ставит очередное периодическое обновление поверх занятого сервиса.
Интервал увеличивается для медленных/неизменных состояний до 60 секунд; ручное
обновление немедленное. При фоновом обновлении выбранный репозиторий имеет
приоритет, остальные проверяются реже. Ограничения глубины/числа каталогов
обнаружения вложенных репозиториев убраны. Список файлов Git имеет страницы
вместо прежнего обрезания на 3000 строках.

Полный статус libgit2 всё ещё строится целиком. Пределы полноценного diff
(8 МиБ / 30 000 строк) и передачи документа LSP (32 МиБ) сохранены. Этот этап
не расширяет эти возможности и не гарантирует задержки на сетевых дисках.

## Проверки

```sh
cmake --build build --target turtle-code-tests -j4
ctest --test-dir build --output-on-failure -LE memory

# Нагрузочный сценарий отдельно, с временными файлами:
./build/turtle-code-workspace-scale-tests --files 160100 --matches 1000000 --line-mib 64
```

`workspace-scale` проверяет правила исключений с Git и без него, полноту индекса,
добавление/удаление файлов, страницы каталога, длинную строку, множество совпадений,
regex-бюджет и отмену. Выводит JSON с длительностями. `project-scale-window`
проверяет страницы дерева и поиска, сохранение выбора и работу таймера GUI.
Размеры штатного теста меньше приведённого нагрузочного запуска.
Реальные DAP/языковые серверы, сетевые файловые системы и оформление реального
рабочего стола требуют своего окружения; offscreen-проверки его не заменяют.

Локальный нагрузочный прогон 14 ноября 2026 года: 160 100 файлов, 1 000 000
совпадений, строка 64 МиБ. Холодное заполнение индекса — 2043 мс, повторный
запрос — 234 мс, поиск — 7043 мс, отмена — 20 мс. Максимальный RSS процесса —
190,98 МиБ; объём временных баз и файлов не входит в эту метрику. Временный
каталог находился на tmpfs, параллельно работали обычные тесты. Это один
синтетический замер, не измерение скорости SSD или сетевой файловой системы.
