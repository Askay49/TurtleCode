# Git

Левая панель Git открывается кнопкой ветки, меню Вид → Git или
`Ctrl+Shift+G` (`view.git`, переназначается в общих shortcuts).
Чтение репозитория и расчёт diff используют libgit2. Для Stage/Unstage, Commit
и переключения веток требуется установленный `git` в PATH. Turtle Code не создаёт репозиторий автоматически.

## Работа

- На окно приходится один проект (одна корневая папка). «Открыть папку»
  заменяет текущий проект; команды добавления папки в workspace нет.
  Если CLI/IPC или старый сеанс передают несколько папок, используется первая
  существующая. Отдельные файлы по-прежнему можно открывать во вкладках.
- Репозиторий определяется по папке проекта, включая открытие вложенной папки
  и Git worktree. Вложенные репозитории рекурсивно не ищутся.
- Верхний список выбирает **локальную ветку**, а не репозиторий. Список
  обновляется вместе со статусом; текущая unborn-ветка также отображается,
  для detached HEAD показывается отдельное состояние. Создание ветки и
  автоматическое создание локальной ветки из remote не реализованы.
  Переключение — `git switch --no-guess -- <branch>` без force, stash или reset.
  Git сохраняет совместимые локальные изменения и отказывает при конфликтующих.
  Ошибка остаётся в панели, список возвращается к фактической ветке.
- Перед сменой ветки несохранённые документы этого репозитория предлагается
  сохранить (Save/Cancel). Ошибка/отмена/Save As в иной путь отменяет переход.
  Открытые файлы блокируются на время перехода. Изменённые на диске документы
  асинхронно перечитываются с сохранением позиции; чистые вкладки файлов,
  отсутствующих на целевой ветке, закрываются. Уже открытый diff скрывается.
  После отказа Git проверяются изменения диска, включая возможное действие hooks.
- Отображаются ветка и четыре группы: подготовленные изменения, изменения
  рабочих файлов, новые файлы и конфликты. Частично подготовленный файл
  присутствует в двух группах. На значке Git нет счётчика; число файлов выбранного
  репозитория доступно во всплывающей подсказке.
- Нажмите файл для сравнения. Рабочая версия находится **слева в штатном
  редакторе Turtle Code**, старая версия — справа, только для чтения. Changes
  сравнивает индекс с живым документом, включая несохранённые правки.
  Рабочий текст редактируется обычным EditorWidget: синтаксис, автопары,
  автодополнение/LSP, выделения, Undo/Redo, поиск и сохранение работают как
  при обычной работе с файлом. Новая копия редактора и отдельная история не
  создаются. Изменённые строки и фрагменты подсвечиваются с обеих сторон.
- При выборе подготовленного файла (Staged) слева также открывается штатный
  редактируемый EditorWidget, справа — HEAD. Подсветка сравнивает HEAD с живым
  рабочим документом, включая неподготовленные и несохранённые правки.
  Временной read-only вкладки индекса нет. Сохранение пишет только рабочий
  файл, индекс меняется исключительно через Stage/Unstage; Commit включает индекс.
  Режим всегда двухколоночный; верхних пояснений, подписей колонок,
  переключателя режима, стрелок и меню сворачивания нет.
- Нижних кнопок «Сохранить» и «Откатить» в diff нет. Сохранение работает
  обычной командой редактора (по умолчанию Ctrl+S).
- ПКМ по файлу в левом Git-дереве открывает меню с «Откатить». Команда
  открывает штатный рабочий редактор и возвращает весь буфер к версии индекса;
  индекс и диск не меняются. Откат отменяется обычным Undo, а для записи
  результата на диск используется сохранение. Для новых файлов, конфликтов
  и удалённых из индекса файлов команда недоступна. Stage/Unstage остаются
  в левом списке Git целыми файлами или группами.
- Прокрутка связывает соответствующие участки старой и новой версии.
  При переключении на другой документ сравнение закрывается, подсветка diff
  в штатном редакторе снимается. При вводе диапазоны пересчитываются в фоне
  с debounce около 100 мс; устаревшие результаты отбрасываются.
- Для новых/удалённых версий используется пустой текст; переименования
  используют исходное имя для HEAD. Для конфликта старая версия — ours,
  слева — обычный рабочий файл с маркерами. Разрешите их, сохраните результат
  и выполните Stage целого файла. Отдельного четырёхколоночного вида нет.
  Бинарные, специальные или слишком большие версии используют read-only patch.
- `+` у файла добавляет его в индекс, `−` убирает из индекса. Те же действия
  у группы применяются ко всем её файлам. Удаление файла и переименование
  учитываются; Unstage сохраняет рабочие файлы. Для первого коммита Unstage
  удаляет запись только из индекса и может отказать, если версии индекса и
  диска расходятся; принудительное удаление не применяется.
- Stage проверяет открытые документы выбранных файлов. Несохранённый файл
  сначала предлагается сохранить (Save/Cancel); после успешной асинхронной
  записи выполняется Stage. Занятый документ требует повторить операцию позже.
  Отмена/ошибка сохранения отменяет Stage. При Save As в другой путь Stage
  исходного набора отменяется. Сама панель не сохраняет документы при Commit.
- Для коммита введите сообщение. Кнопка `Commit` (всегда по-английски) доступна, когда есть подготовленные
  файлы и нет конфликтов. Коммит включает только индекс; остальные изменения
  остаются на диске. Сообщение очищается только после успешного коммита.
  Git hooks, identity, signing и прочая конфигурация Git действуют как обычно.
  Ошибка Commit открывается в отдельном окне с прокручиваемым read-only
  текстом и кнопками «Копировать» (весь текст) / «Закрыть». Текст можно выделить
  и скопировать обычным способом. Сообщение коммита и индекс сохраняются для
  повторной попытки. Окно открывается асинхронно, не блокируя завершение
  обновления статуса Git. Интерактивного запроса терминальных данных нет.

## Обновления и ограничения

Обновление после сохранения, операции Git, открытия панели и возвращения
фокуса приложения. Пока панель видна и приложение активно, состояние
проверяется каждые 2,5 секунды. Кнопка обновления повторяет и обнаружение
репозиториев. Изменение текста сообщения не запускает Git и фоновая проверка
не отключает поле ввода и не добавляет строку прогресса, сдвигающую список.
При изменении списка сохраняются выбранный файл, прокрутка и раскрытие групп. Смена корней очищает сообщение коммита.

Вывод stdout/stderr каждой команды ограничен 8 МиБ; при превышении команда
завершается с ошибкой. Лимит процесса — 5 минут, включая hooks. После timeout
проверьте состояние репозитория перед повтором. Дерево показывает до 3000 строк
с явным уведомлением; действие у группы охватывает все её файлы, включая
непоказанные. Diff показывает до 30 000 строк. Это ограничения просмотра,
а не ограничения размера репозитория. Полные версии ограничены 8 МиБ;
при числе строк свыше 30 000 используется patch. Расчёт сравнения идёт в
фоновом потоке через libgit2/xdiff: прежнего ограничения в 4 млн ячеек LCS
и объединения всей средней части в один блок больше нет. Вывод обычной ошибки в панели сокращается
до 4000 символов; окно ошибки Commit показывает полное сообщение сервиса
в пределах общего лимита вывода команды. Нет фонового бесконечного сканирования каталогов.

Сетевые операции, создание/удаление веток, remote checkout и история коммитов
не входят в эту версию.
Файловые пути передаются как буквальные pathspec, через список аргументов
QProcess без shell. Пути с невалидной кодировкой имени Linux не проверялись.
Qt 6.2.4 отдельно не запускалась.

## Устройство

`src/git/GitBackend.*`: обнаружение репозитория, статус, локальные ветки,
HEAD/индекс (включая конфликтные стадии) и patch через libgit2. Каждый фоновый
вызов владеет своими дескрипторами; чтение не запускает процессы Git.
Зависимость сборки — pkg-config и libgit2 >= 1.1 (Ubuntu: `pkg-config libgit2-dev`,
Arch: `pkgconf libgit2`). Системная библиотека подключается через pkg-config;
её лицензия с исключением для связывания находится в `third_party/libgit2/COPYING`.

`src/git/GitService.*`: асинхронная доставка результатов чтения,
QProcess для операций записи, ограничение вывода, последовательное выполнение операций,
поколения workspace и отбрасывание устаревших ответов. Смена workspace не
прерывает уже начатую запись индекса/коммит. Закрытие окна во время такой
операции отклоняется с сообщением; после её окончания закрытие нужно повторить.

`GitPanel.*`: список файлов, выбор локальной ветки, Stage/Unstage и сообщение коммита.
`GitDiffModel.hpp`: построчное сравнение через `git_diff_buffers`, сопоставление строк,
выбор частичных изменений и генерация patch с сохранением EOF/CRLF.
`GitDiffView.*`: минимальный QDockWidget старой версии; новый рабочий текст
остаётся в штатном редакторе, в том числе при выборе Staged.
MainWindow связывает старую версию с действующим EditorWidget; сравнение
не создаёт второго редактируемого документа. EditorWidget рисует диапазоны diff
поверх обычного редактора без изменения содержимого и истории.
Версии обновляются после записи Git и раз в 2,5 с у активной видимой панели;
живой буфер — с debounce около 100 мс. Сохраняются курсор и прокрутка, поздние
результаты сравнения отбрасываются. Сервисный API частичных операций сохранён и проверяется тестами, но в текущем
минимальном интерфейсе кнопки Stage выбранных строк нет.

Проверки `git` используют временные настоящие репозитории; `git-window`
проверяет интеграцию с MainWindow, Save/Cancel перед Stage и переключением ветки,
перечитывание редактора и отказ Git без потери локальных правок. Git-тесты
пропускаются, если исполняемый Git отсутствует. Для offscreen-снимка реального
окна тест принимает `TURTLE_CODE_GIT_PREVIEW=/absolute/path.png`.

При первом открытии файла через Git сравнение связывается со штатным
редактором ещё во время фоновой загрузки. Дополнительная копия новой версии
не появляется; повторное открытие использует тот же редактор.

Сохранение без изменения байтов сразу восстанавливает готовую подсветку diff,
не дожидаясь периодической проверки Git. Повторный ответ с теми же версиями
не пересчитывает diff; во время сохранения дисковый снимок не подменяет живой
буфер. Устаревшая модель не применяется к новым правкам.


Проверка готовности живого документа остаётся раз в 200 мс, но полный текст
считывается только при уведомлении об изменении или переходе busy → ready.
Сохранение с прежними байтами по-прежнему восстанавливает подсветку сразу.
Дополнительные тесты покрывают чтение без Git в PATH, разнесённые изменения
в большом файле, CRLF/EOF/нулевые байты, все семь типов конфликтов и их стадии,
symlink/бинарные/большие версии и отсутствие повторного чтения неизменного документа.


Визуальная модель сравнивает CRLF и LF как одинаковый перевод строки:
разница только в скрытом CR больше не окрашивает одинаковые строки.
Пробелы, табуляция и отсутствие завершающего перевода строки остаются
изменениями. Исходные байты снимков сохраняются; статус Git продолжает
учитывать реальные изменения окончаний строк. Сервисное сравнение/patch
по-прежнему использует исходные байты. Само отображение не переписывает файлы.
End, выделение до конца строки, мышь и посимвольная навигация редактора
не ставят курсор между CR и LF. Backspace/Delete через границу строки
удаляют весь CRLF, а замена видимого текста строки сохраняет её CRLF.
