# Git

Левая панель Git открывается кнопкой ветки, через **Вид → Git** или
`Ctrl+Shift+G` (`view.git`). Чтение репозитория и расчёт diff используют libgit2.
Для записи индекса, коммитов, смены веток и сетевых операций нужен `git` в PATH.
Репозиторий создаётся обычными инструментами Git.

## Репозитории и ветки

На окно приходится один проект. «Открыть папку» меняет его корень. Если CLI/IPC
или старый сеанс передаёт несколько папок, используется первая существующая.
По корню проекта определяются содержащий его репозиторий и доступные вложенные
репозитории, включая worktree. Вложенные репозитории обнаруживаются в фоне по
правилам обхода проекта. У каждого репозитория своя секция с веткой,
сообщением коммита и изменениями. Значок Git показывает общее число изменённых
файлов по найденным репозиториям.

Список в заголовке каждой секции выбирает локальную ветку. Для detached HEAD
показывается отдельное состояние. Переключение выполняется через
`git switch --no-guess -- <branch>`. Git сохраняет совместимые локальные
изменения и отказывает при конфликтующих.

Меню репозитория содержит Fetch, Push и Pull в режиме fast-forward only.
Используются `git fetch --all --prune`, `git push` и `git pull --ff-only`.
Параметры remotes, upstream и аутентификации берутся из конфигурации Git.
Интерактивный терминальный запрос не поддерживается.

Перед сменой ветки и Pull редактор предлагает сохранить затронутые
несохранённые документы. Save As в другой путь, отмена или ошибка записи
прерывают операцию. Во время перехода затронутые документы блокируются.
После него изменившиеся файлы перечитываются с сохранением позиции, а чистые
вкладки исчезнувших файлов закрываются. Открытый diff скрывается перед переходом.
После ошибки Git тоже проверяются изменения на диске.

## Изменения и сравнение

- Подготовленные изменения и изменения рабочих файлов показываются
  отдельно от конфликтов. Новые файлы входят в «Изменения» с меткой `U`.
  Частично подготовленный файл может присутствовать в обеих группах.
- Клик по файлу открывает сравнение внутри области редактора. Слева находится
  исходная версия только для чтения, справа — штатный рабочий редактор с
  подсветкой, поиском, LSP, сохранением и Undo. Outline возвращается при
  закрытии сравнения, если был виден до него.
- Для «Изменений» слева показан индекс. Для Staged слева показан HEAD.
  Сравнение включает живые правки справа, в том числе несохранённые.
  При конфликте слева показана версия ours, справа — рабочий файл с маркерами.
  Бинарные, специальные и большие версии могут открываться в виде patch.
- Обе стороны прокручиваются одной вертикальной полосой справа. Цветные
  метки рядом с ползунком показывают добавления, удаления и правки по всей
  длине сравнения. Нажатие на полосу с метками переносит к нужному участку.
  Пустые промежутки выравнивают строки без вставки в документ. При вводе
  обе панели сохраняют выравнивание и учитывают вставки и удаления строк
  до завершения фонового пересчёта. Очередь хранит только последнюю ревизию.
  Переключение на другой документ закрывает сравнение.
- «Откатить» в меню либо значок отката у файла восстанавливает рабочий
  буфер из индекса и сохраняет файл обычным механизмом редактора. Undo
  возвращает прежний текст как несохранённую правку. Индекс сохраняется,
  а ошибки записи обрабатываются как при обычном сохранении.
- Отдельная команда «Отменить изменения…» подтверждает восстановление
  рабочего файла из индекса через Git, включая открытые несохранённые правки.
  Для новых файлов, конфликтов, удалённых из индекса файлов и переименований
  в рабочем дереве эта команда недоступна. При ошибке буфер сохраняется.

## Индекс и коммит

`+` добавляет файл в индекс, `−` убирает его из индекса. Действие у группы
охватывает все её файлы, включая другие страницы. Stage предлагает сохранить
несохранённые открытые документы и ждёт успешного сохранения. Занятый документ,
ошибка, отмена и Save As в другой путь останавливают Stage. До первого коммита
Unstage удаляет запись из индекса и может отказаться при расхождении с диском.
Обычное сохранение меняет только рабочий файл.

Введите сообщение и нажмите **Commit** или `Ctrl+Enter` в поле сообщения.
Коммит включает индекс. Если подготовленных изменений ещё нет, редактор
предлагает сначала подготовить все изменения. В меню кнопки есть явная команда
Stage all and commit.
Конфликты блокируют коммит. Черновик принадлежит своему репозиторию и очищается
после успешного коммита. Ошибка открывается в отдельном окне с возможностью
скопировать полный вывод. Индекс и сообщение остаются для повторной попытки.

## Обновление и пределы

Обновление запускается после сохранения, операций Git, открытия панели и
возврата фокуса приложения. Пока панель видна и окно активно, периодический интервал
адаптируется от 2,5 до 60 секунд. Выбранный репозиторий проверяется чаще.
Общая кнопка Refresh повторяет обнаружение репозиториев. Список изменений
показывается страницами примерно по 500 строк. Выбор и прокрутка сохраняются,
когда соответствующий файл остаётся на странице.

Команда Git может вернуть до 8 МиБ отдельно в stdout и stderr. Таймаут
процесса составляет пять минут, включая hooks. При превышении операция
завершается с ошибкой. Полные версии для сравнения ограничены 8 МиБ,
а полноценный diff — 30 000 строк. За этими пределами используется patch.

При визуальном сравнении LF и CRLF считаются одинаковым переводом строки.
Пробелы, табуляция и отсутствие финального перевода строки остаются
значимыми. Исходные байты передаются в Git. Подробнее о масштабировании
и фильтрах обхода в [LARGE_PROJECTS.md](LARGE_PROJECTS.md).

## Устройство и проверки

- `src/git/GitBackend.*` читает репозитории, ветки, статус, HEAD, индекс и
  конфликтные стадии через libgit2. Каждый фоновый вызов владеет своими
  дескрипторами. Зависимость и лицензия описаны в
  [third_party/libgit2](../third_party/libgit2/).
- `GitService.*` управляет фоновым обнаружением и чтением, выполняет операции
  записи через QProcess, передаёт аргументы списком и отбрасывает устаревшие
  результаты по поколению workspace. Начатая запись индекса или коммит
  завершаются при смене workspace. Во время записи окно нельзя закрыть.
- `GitPanel.*` обслуживает секции репозиториев и действия, `GitDiffModel.hpp`
  сопоставляет строки через `git_diff_buffers`, `GitDiffView.*` связывает
  исходную версию с действующим `EditorWidget`. Обычный просмотр сравнения
  сохраняет текст и историю рабочего редактора. Вывод с диска не подменяет
  живой буфер, а поздние результаты сравнения отбрасываются. Частичный Stage
  есть в сервисе. Панель работает с целыми файлами и группами.
- `git` проверяет работу с временными репозиториями, включая сетевые команды
  через локальный bare-репозиторий. `git-window` проверяет интеграцию с окном,
  сохранение перед Stage и переключением ветки, откат, состояние диска и Undo.
  При отсутствии Git соответствующие проверки пропускаются. Для снимка окна
  в `git-window` можно задать `TURTLE_CODE_GIT_PREVIEW=/absolute/path.png`.
