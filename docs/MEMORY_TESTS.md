# Автоматические проверки памяти (Linux)

Это отдельные интеграционные тесты настоящего `MainWindow` и `EditorWidget`.
Они не запускают установленный пользовательский экземпляр, не меняют его настройки
и не требуют сторонних Python-пакетов. Нужны Python 3.8+ и читаемый
`/proc/PID/smaps_rollup`. Интерфейс работает через Qt offscreen.

## Запуск

Из корня проекта:

```sh
cmake -S . -B build -DTURTLE_CODE_MEMORY_TESTS=ON
cmake --build build --target turtle-code-window-tests -j4

# Быстрая проверка: файл 10 МиБ, шесть циклов
ctest --test-dir build -R '^memory-10mib$' --output-on-failure

# Все три размера: 10, 100 и 500 МиБ, по шесть циклов
ctest --test-dir build -L memory --output-on-failure

# Обычные тесты без тяжёлых проверок памяти
ctest --test-dir build -LE memory --output-on-failure
```

Опция регистрации по умолчанию выключена. Даже при её включении автоматический
Отдельная цель `turtle-code-check` исключает метку `memory`. Обычная сборка тесты не запускает.
Прямой `ctest` без фильтра запускает все зарегистрированные тесты, включая память.
Проверки памяти выполняются последовательно. Для сценария 500 МиБ нужно несколько
гигабайт свободного временного диска; потребление зависит от backing files и истории.

## Что происходит

Один свежий процесс на размер файла; внутри него сохраняется одно окно и выполняются
шесть циклов:

1. Открыть файл и дождаться загрузки.
2. Вставить 1 МиБ через настоящий clipboard/paste.
3. Выделить всё и удалить.
4. Undo, Redo, затем два Undo до исходного сохранённого состояния.
5. Закрыть вкладку штатным обработчиком, очистить clipboard.
6. Дождаться уничтожения редактора и документа, обработать deferred deletion,
   дать фоновым задачам дополнительную секунду и измерить состояние после закрытия.

Проверяется размер текста на каждом этапе, modified/save-point и освобождение
владельцев документа. Файл генерируется порциями, без полной копии в памяти runner.
Пользовательские файлы не используются; временные данные удаляются после прогона.
Подсветка C++, LSP и recovery выключены; файл plain text. Эти тесты проверяют
память редактора и историю, **не** нагрузку Tree-sitter, clangd или recovery.

## Отчёты и критерий ошибки

`build/memory-reports/10mib/` (аналогично `100mib`, `500mib`) содержит:

- `summary.json`: результат, измеренные пики, замеры после закрытия, временные
  отметки этапов, причины ошибки;
- `samples.csv`: временной ряд RSS/PSS редактора, отдельно дочерних процессов и
  выделенного места временных файлов, включая открытые удалённые backing files;
- `stderr.log`: сообщения Qt и ошибки сценария;
- `progress.json`: последний достигнутый этап, доступен во время выполнения.

CSV дописывается во время прогона, поэтому замеры доступны даже до его завершения.

Файлы отчёта перезаписываются следующим запуском того же размера.
RSS/PSS снимаются примерно каждые 50–100 мс (на медленной системе реже).
Это **измеренные выборочные пики**, короткий всплеск между замерами может быть пропущен.
Отметки этапов позволяют оценивать длительность, но включают служебные ожидания;
это не измерение задержки каждого нажатия клавиши. Диск измеряется для изолированной
временной папки теста, включая его временную конфигурацию; исходный fixture исключён.

Первый закрытый цикл служит прогревом. По умолчанию тест падает, если RSS **или**
PSS после любого последующего закрытия превышает первый замер более чем на 64 МиБ.
Также ошибкой считаются неполный сценарий, неверный результат операции, оставшийся
владелец документа, аварийный выход и тайм-аут. Дочерние процессы и временный диск
пока только отражаются в отчёте, отдельных лимитов для них нет.

64 МиБ — начальный настраиваемый допуск, не доказательство отсутствия утечек и не
общий лимит памяти приложения. Он допускает удержание страниц аллокатором и кэшами;
малый накопительный рост может остаться ниже порога. Для сравнения изменений
сохраняйте отчёты и используйте одинаковую сборку, систему и входные параметры.

Для другого размера, числа циклов или допуска:

```sh
python3 tests/MemoryRegression.py \
  --binary build/turtle-code-window-tests \
  --size-mib 100 --cycles 10 --max-growth-mib 32 \
  --report build/memory-reports/custom
```

Общий тайм-аут runner по умолчанию 1200 секунд (`--timeout`), CTest — 1260 секунд
на сценарий. Код возврата runner: 0 при успехе, ненулевой при ошибке.
