# EditorConfig

Turtle Code автоматически читает `.editorconfig` для пути каждого документа.
Разбор выполняет EditorConfig Core C: поддерживаются маски секций, вложенные
файлы, поиск в родительских каталогах, `root = true` и `unset`. Правила ближайшего
файла и поздних подходящих секций имеют приоритет. Без подходящих настроек
сохраняется прежнее поведение редактора.

В корне исходников Turtle Code добавлен `.editorconfig`: 4 пробела, UTF-8, LF,
очистка хвостовых пробелов и перевод строки в конце; для JSON/YAML — 2 пробела,
для Makefile — табуляция. Хвостовые пробелы Markdown сохраняются, а `third_party/`
исключён из этих правил через `unset`. Существующие исходники массово не переписаны.

## Поддерживаемые свойства

| Свойство | Поведение |
| --- | --- |
| `indent_style` | `space` / `tab` для Tab, отступа выделенных строк и дополнительного отступа после `{` |
| `indent_size` | Размер отступа 1–256, включая `tab` |
| `tab_width` | Ширина табуляции 1–256 для отрисовки, курсора, кликов, выделений и миникарты |
| `end_of_line` | `lf` / `crlf`: Enter и нормализация при сохранении |
| `trim_trailing_whitespace` | При `true` удаляет пробелы и табуляции в конце строк и файла при сохранении |
| `insert_final_newline` | При `true` добавляет завершающий перевод строки непустому документу; при `false` убирает завершающие переводы строк |
| `charset` | `utf-8` / `utf-8-bom`: удаление или добавление UTF-8 BOM при сохранении |

LSP-форматирование получает актуальные `tabSize` и `insertSpaces`; дальнейшая
интерпретация параметров зависит от сервера и его настроек форматирования.
Существующие отступы не переформатируются автоматически при открытии.

Настройки перечитываются при открытии/перезагрузке документа, изменении пути,
возвращении фокуса, Tab/Enter, форматировании и сохранении. Сохранение
`.editorconfig` внутри Turtle Code обновляет настройки уже открытых документов
во всех окнах. Для несохранённого документа без пути действуют настройки по
умолчанию; после выбора пути Save As применяются правила целевого каталога.

## Сохранение и ограничения

Нормализация готовится в фоне на независимом снимке документа. Данные читаются
порциями, а изменяемые диапазоны для Undo хранятся в дисковом payload. Метаданные
истории растут с числом изменённых строк. Во время подготовки документ занят;
отмена и ошибки подготовки оставляют исходный буфер и историю без изменений.
Успешная нормализация — одно действие Undo; повторное сохранение уже чистого
документа не добавляет действие и не снимает выделение.

После подготовки используется обычное атомарное сохранение с проверкой внешних
изменений. Если запись файла не удалась или была отменена на этом следующем
этапе, успешно подготовленные изменения остаются в буфере как несохранённые
и отменяются Undo. Undo после успешного сохранения также не переписывает диск.

Редактор остаётся UTF-8-ориентированным: `latin1`, `utf-16le`, `utf-16be` и
`end_of_line=cr` пока не конвертируются. Показывается предупреждение, а это
свойство игнорируется; остальные поддерживаемые правила продолжают действовать.
Некорректный файл конфигурации вызывает предупреждение и откат к обычным
настройкам. Неизвестные свойства и недопустимые значения игнорируются.
Для строк длиннее 64 КиБ сохраняется существующий упрощённый режим отрисовки.

## Сборка и проверки

Нужен EditorConfig Core C (Ubuntu: `sudo apt-get install libeditorconfig-dev`).
GitHub Actions устанавливает пакет, linuxdeploy включает библиотеку в AppImage.
На компьютере пользователя готового AppImage устанавливать её отдельно не нужно.

```sh
cmake --build build --target turtle-code-editorconfig-tests turtle-code-editor-tests turtle-code-window-tests -j4
ctest --test-dir build -R '^(editorconfig|editor-widget|formatting|window-shutdown|document-safety)$' --output-on-failure
```

Тесты проверяют наследование/маски/`unset`, Tab/Enter, геометрию табуляции,
опции LSP, нормализацию BOM/CRLF/Unicode/длинных хвостов пробелов, Undo/Redo,
отмену подготовки, отсутствие лишнего Undo и обычное сохранение через MainWindow.
